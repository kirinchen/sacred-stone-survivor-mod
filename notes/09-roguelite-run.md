# 09 Roguelite:一局流程、永久進度、「倖存者」選單

> 2026-11-22 ~ 23(設計見 [06](06-roguelite-design.md))。
> 遊戲 V2.85;位址只對這個版本。程式在 `mod/src/rogue.c`(由 `sssmod.c` include)。
> 裝備 / 被動 / 夥伴 / 換主角在 [10](10-equipment-passive-partner-lead.md)。

## 結論

- **整條流程接起來了**:標題畫面按「倖存者」(或 F9)→ 選地圖 → 進場自動開局 → 10 分鐘內打倒頭目過關 / 主角倒下失敗 → 結算 → 回選單。
- **永久進度**存 `game/sss_meta.json`(錢、過關幾張、技能格、角色、裝備、被動),原作存檔不寫。
- **每局從頭**不靠重讀存檔(遊戲中重讀會當),改成開局記下隊伍數值、結束整塊還原。
- **主角不會真的死**:原作的死亡流程會跳「進度讀取」選單,之後換圖就當 → 把命墊高,掉到墊高值以下算倒下。
- 8 張圖都是原作頭目(2026-11-23 把 263 張圖掃完找到配對,見 [12](12-auto-pickup-boss-pairs.md))。
- 掉落物靠近自動撿、補內力的丹藥自動喝,也在 [12](12-auto-pickup-boss-pairs.md)。

## 一局

| 時間 | 發生什麼 |
|---|---|
| 0:00 | 進場,主角搬到地圖中央;圖上原作自帶的怪留著,數值一樣被壓過 |
| 每 5 秒 | 生一波:3 + 每 30 秒多 1 隻;場上上限 30 起、每 8 秒 +1、最多 80 |
| 0:40 起 | 每隔一段加一種新的怪(蝙蝠 → 蜘蛛 → 刀手 → 蟾蜍 → 弓手 → 強化版) |
| 2:00 / 4:00 / 6:00 | 精英:血 ×5、攻 ×1.3;倒下 +10 錢,60% 掉裝備 |
| 8:00 | 頭目出場:血 ×22、攻 ×1.3、招式威力壓到 25%、放招機率壓到 35%、會黏著主角(離 36 px 以上就往主角挪);小怪減半、場上最多 45 隻 |
| 10:00 | 頭目狂暴:攻 ×2 |
| 頭目倒下 | 過關:+50 錢、過關獎勵 100 × 第幾張圖、解鎖下一張、掉 1 件裝備 + 1 個被動 |
| 主角的命歸零 | 失敗:錢、撿到的裝備照留 |

**怪的數值**一律壓到同一條曲線上(`rg_norm`),不管原作那隻怪多強 —— 所以中後期的圖也不會秒殺 Lv 1 主角:

- 第 `m` 張圖(0 起)、時間進度 `d = t / 8:00`(到 10:00 封頂)
- 命 = (12 + 6m) × (1 + 4d) × 體型係數(原作命 ÷ 35,夾在 0.6–1.6)
- 攻 = (6 + 3m) × (1 + 3d) × 攻擊係數(原作攻 ÷ 30,夾在 0.75–1.35)+ 主角等級 × 0.6(不然防禦一路疊上去,怪每下只打 1)
- 防 ≤ 2 + 2m + 10d;等級 ≤ 1 + 2m + 8d
- **原作經驗給 0**:原作升級會把命上限重算回表上的值,等級也不該留。成長只靠模組的 3 選 1,另外每升一級自帶 攻 +1、防 +1、命上限 +8。

**擋換地圖**:一局中主角走進出口會被原作換圖。掛在兩支換圖請求函式(`0x419980` / `0x4198a0`)開頭,一局中直接不做。

**受傷上限**:主角一下最多掉命上限的 15%、一秒最多掉 12%,多的補回去(`rghitcap 單發% 每秒%` 可調)。

**頭目 / 精英優先**:普攻本來只打最近的 3 隻,被小怪圍住時輪不到頭目 → 頭目 / 精英在範圍內就一定算進去;絕招一半對著頭目放。

## 永久進度 `game/sss_meta.json`

```json
{ "v": 1, "money": 211, "cleared": 0, "slots": 3, "lead": 1, "runs": 1, "wins": 0,
  "chars": [1], "items": [302, 1, 1], "eq": [0, 0, 0, 302], "pas": [], "pas_eq": [0, 0] }
```

- `items` 三個一組:物品 id、等級、有幾件。`eq` = 主角四格裝的物品 id(0 = 起始那件)。`pas_eq` = 主角、夥伴裝的被動。
- 結算時寫一次,撿到裝備、在選單買東西時也寫。先寫 `.tmp` 再換名。
- 刪掉這個檔 = 從頭開始。

## 做法上的幾個決定

### 每局從頭:記下來、結束還原

- 隊伍每個人的數值區塊是 `gs+0x44[0..7]`(第 k 格 = 角色 k+1)。
- 開局 `snap_take`:每格的 `+0x3c..+0x93`(等級、經驗、命、內、攻、防、抗、裝備四格)和會的招記下來。
- 結束 `snap_restore`:整塊寫回去、多學的招忘掉、叫原作重算。
- 開局另外把主角壓到同一條起跑線:Lv 1、命 122、內 97、攻防抗各 10、最基本的四件裝備 —— 不管存檔裡練到幾級。

### 主角不能真的死

- 原作主角一死就跳「進度讀取 / 回主選單」選單;那個狀態下換圖會當。
- 一局中把主角命上限和現在的命都加 30000;掉到 30000 以下 = 倒下,模組立刻暫停、出結算。
- 原作 HUD 的命條和數字會顯示墊高的值 → 模組在同一個位置蓋掉重畫。

### 暫停時的選單

- 遊戲裡開選單 / 結算 = 設原作的暫停旗標 `app+0x12`。暫停時原作不出新畫面。
- 選單內容變了就自己把 overlay 重畫到上一幀的 back buffer,再照上一次的參數 Blt 一次(`ui_present`)。
- 標題畫面不暫停,照常每幀畫。

## 踩到的坑

| 坑 | 原因 / 處理 |
|---|---|
| 從選單開局馬上「逾時」,接著 `c0000005` | `stage.ini` 那幾支原作函式(`0x46ecf0` / `0x46ed20` / `0x46ec00` / `0x450590`)會弄壞 ebx / esi / edi,回到模組後暫存器裡的變數變垃圾。加一個自己存 / 還原暫存器的跳板 `safe_cdecl` |
| 遊戲中直接叫讀檔 `0x4261b0` 當掉 | 當在 `0x42bd00`:讀檔後原作更新 HUD(`0x418fd0 → 0x41a300 → 0x419b80`),找不到 `scene+0x18` 那個視窗。標題畫面叫同一支沒事。改成不重讀 |
| 開局 6 秒就被判倒下 | 原作升級把命上限重算回表上的值,墊高的 30000 沒了。原作經驗改給 0;另外每幀檢查,被重算掉就補回去 |
| 絕招整局沒放 | 牽繩距離設 1000000,平方溢位。改 30000 |
| 掃圖時 `god 1` 擋不住 | 一擊超過命上限就死。之後要掃圖得用墊高命的做法 |
| 選單開著時截圖沒反應 | 暫停中沒有新的一幀。截圖前先 `ui_present` |

這幾局查出來的三個原因:

- **遠程怪堆積**:弓手之類停在射程外不靠近,主角普攻(60 px)砍不到,牠們把場上 80 隻的名額佔滿、新怪生不出來。→ 遠程怪(`stat+0x78 > 0`)場上最多 10 隻。
- **原作重算把命上限壓到 999**:每次升級選項後呼叫原作重算 `0x408680`,墊高的 30000 被壓掉,補救程式又把命上限補成 999 → 前面幾局主角其實從第一次升級起就是 999 命。→ 重算前先把墊高的拿掉、算完加回去(`recalc_keep`)。
- **頭目連續放招**:盲劍的 AI 定義放招機率 80%。每一下不超過 155,但很密。→ 放招機率壓到 25(結束還原),另外加每秒受傷上限。

第六局偏鬆也偏拖(主角幾乎不掉血,狂暴後又打了 3 分 26 秒)。可調的地方:`rg_norm` 的曲線、`rghpx`(頭目 / 精英血量倍率)、`rghitcap 單發% 每秒%`。

代玩腳本只會繞著地圖中央走小圈、升級選項照固定優先序選,不代表人手的表現。
