# 08 邊砍邊走 + 技能 CD + 技能格

> 2026-11-22(Roguelite 設計 的第二步)。
> 遊戲 V2.85;位址只對這個版本。程式在 `mod/src/sssmod.c`「邊砍邊走」「技能格 / CD」兩段。

## 結論

- **邊砍邊走做得到,兩種做法都會動**,預設用 A。主角照玩家點的地方走,普攻自動結算,不再被拉去站定。
- **每招 CD**:原作沒有每招計時的冷卻(只有內力、動作鎖、「同一招還在場上」三道檢查),模組自己記。掛在原作放招函式開頭,**模組自動放、玩家右鍵、原作的「收招後自動放」三條路都擋得到**。
- **技能格**:3 格起(`survslots N`,最多 8)。只有格子裡的招放得出來;升級學到的招放進空格,格子滿了就不再出「學新絕招」;**這一局學的招結束時忘掉**(技能不保留)。花錢解鎖格子還沒接。
- 放絕招時主角還是會停下來(原作的放招動作鎖),這輪沒處理。

## 邊砍邊走:三種方式(指令 `survatk N`)

| N | 做法 | 攻擊動作 | 傷害怎麼算 |
|---|---|---|---|
| 0 | v1:叫原作普攻 `0x447230`,主角走到目標旁站定揮刀 | 原作的 | 原作命中幀 |
| **1(預設)A** | 主角維持走路指令;模組每 550 ms 對 60 px 內最近的 3 隻敵人直接呼叫原作的普攻結算 `0x43d780`,再播一次攻擊動作當視覺(`0x440ae0`,不鎖指令) | 邊走邊播 Attack1 / 2 | 模組定時呼叫原作結算(命中判定、傷害數字、Miss 字、硬直、死亡、經驗都是原作的) |
| 2 B | 射程內有敵人就叫原作起手 `0x4441a0`(真的揮刀);揮刀期間模組寫速度 `obj+0x2c / +0x30` 讓主角繼續往目的地滑,並把目的地排隊(收招後原作自己接著走) | 原作的揮刀,邊揮邊滑 | 原作命中幀 |

可調:`survswing 間隔ms 範圍px 最多幾隻 動作(0 不播 / 1 / 2 強制重播) 結算(0/1) 設目標(0/1)`。

### 實測

量法:`tools/atk_test.sh MODE`。每次重新讀檔,琉璃仙境通道,命鎖滿、不升級,主角每 2.5 秒在 (320,330) / (320,620) 之間來回走,跑 32 秒;看 log `v1 end` 行。**每種 1 次**(B 第二次錄影時是 960 px)。

| | 走了多遠 | 在走路的時間 | 被動作鎖住的時間 | 普攻次數 | 擊殺(含戰友、絕招) |
|---|---|---|---|---|---|
| 0 原作站定 | 430 px | 8% | 75% | 118 次指令 | 30 |
| 1 A 模組結算 | 1461 px | 43% | 13% | 25 刀(命中 37、Miss 10、砍死 17) | 37 |
| 2 B 原作揮刀 + 滑行 | 1555 px | 22% | 43% | 17 刀 | 36 |
| A,不放絕招 | 1920–2135 px | 68–69% | 3% | 29–34 刀 | — |

- A 剩下的 13% 鎖定是放絕招的動作;不放絕招就只剩 3%。
- **A 不會重複扣血**:只播攻擊動作、不叫結算(`survswing 550 60 1 1 0 1`),27–29 刀裡目標的命只有 1–2 次有變(戰友打的),有沒有把目標寫進 `obj+0x13c` 都一樣 → 動作本身不會結算傷害。
- 動作好不好看只看了錄影抽幀:A 走路中會出現揮刀姿勢和傷害數字;B 是原作完整的揮刀。**沒有真人手感測試**。
- A 沒有打擊火花和打擊音(那些在原作的動畫幀腳本裡,不在結算函式裡)。

### 選 A 的理由

- 不搶玩家的走路指令,被鎖住的時間最少。
- 一刀可以打多隻(範圍傷害),倖存者要的就是這個;B 一刀只打原作鎖定的那一隻。
- B 的好處是動作和打擊感完全是原作的;留著當選項(`survatk 2`)。

## 技能格 + CD

| 指令 | 作用 |
|---|---|
| `survslots N` | 技能格數(預設 3,1–8);下一局生效 |
| `survcd 0 0` / `survcd 1 0` | 關 / 開 CD 與技能格(關掉 = v1 的固定間隔) |
| `survcd 招式id 毫秒` | 指定某招的 CD |
| `survcdbase 基礎ms 每點內力ms` | 預設公式:CD = 2.5 秒 + 內力消耗 × 0.05 秒(龍氣劍內力 12 → 3.1 秒;內力 60 的招 5.5 秒) |
| `slots` | 印每格的招、CD、還剩多久 |
| `cast N` | 測試用:對最近的敵人放「會的第 N 招」 |

- 開局:主角原本會的招照順序放進格子,放不下的這局不能用。
- 自動放招:格子裡 CD 好了的招輪流放,兩招之間至少隔 0.7 秒。
- 升級「絕招間隔 −20%」改成「絕招冷卻 −20%」(所有 CD ×0.8)。
- 畫面第三行顯示技能格:`[1 龍氣劍 1.6] [2 空] [3 空]`(數字 = 還剩幾秒)。

| 測什麼 | 結果 |

| CD 擋不擋得住 | 放一次(內力 93 → 81)→ 1.2 秒後再放:擋下 → 再過 2.5 秒:放得出來 |

每項 1 次。

## 逆向到的東西

| 位址 | 是什麼 |
|---|---|
| `0x43d780` cdecl `(attackerId, targetId, 0)` | **普攻結算**(腳本內建函式,exe 裡沒有直接呼叫它的地方)。回傳 0 無效 / Miss、1 命中、2 命中 + 硬直、3 擊殺。🔴 第三個參數槽會被它拿去當暫存,一定要給 |
| `0x440ae0` thiscall `(obj, 動作)` | 設動作:0 / 1 站、2 / 3 走、4–7 Attack1–4、8 / 9 SPAttack、0xa / 0xb 射擊、0xc–0x10 放招、0x13 受創、0x19–0x1b 衝刺攻擊。跟目前動作相同就不重播 |
| `0x440bb0` thiscall `(obj, 動作)` | 一次性覆蓋動作(寫 `obj+0xb4`),可強制重播 |
| `0x4441a0` thiscall `(obj, targetId)` | 原作「試著出手」:在射程內且沒被擋就起手揮刀,回 1 |
| `0x442390` thiscall `(obj, ctx)` | 物件每幀 update:計時器 → 動作鎖 `+0x188` 倒數(歸零時依 `+0x184` 收招)→ 指令分派 → 位移 `0x444640` → 動畫 |
| `0x449080` | 玩家輸入處理:左鍵點地 / 按住 → `0x445a80`(按住會每幀重下 = 原作本來就能按住持續走);點敵人 → `0x447230`;右鍵 → `0x446e80` |
| `0x446e80` → `0x446fc0` | 放招。檢查順序:地圖可戰鬥 → can-act → 不在受創 → 同一招不在場上 → 內力夠。**沒有每招計時 CD** |
| `0x407f70` thiscall `(stat, moveId)` | 忘掉絕招 |
| `obj+0xb0 / +0xb4` | 目前動作 / 一次性覆蓋動作 |
| `obj+0x184` | 動作鎖的種類(1 近戰、3 射擊、4 絕招 / 硬直) |
| `obj+0x18e`(byte) | 有排隊的走路目的地(動作鎖內下「走到」只會記下來,收招時執行) |
| `obj+0x2c / +0x30` | 速度(16.16,每幀) |
| `stat+0x70 / +0x78` | 近戰 / 遠程射程(格) |
| `stat+0x74` | 連段數 |
| `stat+0x104..+0x110` | Attack1–4 的動作鎖幀數(= 攻速) |

模組掛勾:`0x446e80` 開頭 8 個位元組(`mov eax,[esp+4] / push esi / mov esi,ecx / push eax`)換成跳到模組;安裝前比對位元組,不對就不裝(只剩自動放招有 CD)。

## 坑

- `tools/relaunch.sh` 原本用 `grep -E "error|BUILD OK" || exit 1` 判斷編譯結果 —— 編譯失敗的輸出裡有 `error`,grep 一樣算成功,結果拿舊 DLL 跑了一輪測試才發現數字欄位沒出來。改成一定要看到 `BUILD OK`。
- PowerShell 5 讀不了沒有 BOM 的 UTF-8 腳本(`tools/obs_session.ps1` 有中文註解),要用 `pwsh`。
