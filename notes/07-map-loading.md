# 07 直接載入指定地圖(`goto_map`)

> 2026-11-22(Roguelite 設計 的第一步:最大風險)。
> 遊戲 V2.85;位址只對這個版本。程式在 `mod/src/sssmod.c`「地圖」段。

## 結論

- **做得到**。模組指令 `goto_map <id>` 可以從任何一張地圖直接跳到指定地圖,約 0.4 秒,主角、戰友、原作那張圖的怪都在。
- 原作換地圖是**排程式**的:呼叫「請求換地圖」函式寫一筆待辦,主迴圈自己淡出 → 拆舊圖 → 載新圖 → 淡入。模組只要呼叫請求函式,不用自己拆圖。
- **不會蓋存檔**:換圖期間暫時關掉原作的自動存檔(改 1 個位元組,到站改回)。實測存檔 md5 前後相同。
- **從標題畫面**:也可以。標題畫面下 `goto_map 38`,模組先叫原作讀自動存檔(`0x4261b0(app, 0x14)`),進到遊戲後接著換圖,從下指令到站在李家莊約 3 秒(1 次)。隊伍、等級就是那份存檔的
- **地圖表**:`stage.ini` 有 263 張(id 0–743)。標 `STAGE_WAR`(戰鬥地圖)且 id < 140 的有 80 張,逐張跳過一輪:**80 張都到得了**(其中 2 張第一輪當掉,原因是主角在前一張圖已經被打死,不是地圖載不進來;見「實測」)。

## 指令

| 指令 | 作用 |
|---|---|
| `goto_map ID` | 目標圖有 1 號出口就從 1 號出口進;沒有就放在格 (10,10) 再挪到最近可走格 |
| `goto_map ID gw N` | 從 N 號出口進 |
| `goto_map ID X Y` | 放在格 (X,Y)(一格 16 px),到站後挪到最近可走格 |
| `maps [LO HI]` | 列 `stage.ini` 的地圖:id、名字、類型、出口 → log 和 `game/sss_maps.tsv` |
| `where` | 印目前地圖 id / 名字 / 大小 / 旗標 / 主角位置 / 物件數 |

`tools/map_test.sh ID...`:逐張跳、等 4 秒、印結果;遊戲死了會重讀檔並記 `CRASH`。

## 原作怎麼換地圖

全域:`gs = *0x4c3214`(`+0x10` 目前 stage)、模式管理器 `*0x4c31f8`,**`scene = *(模式管理器 + 0x14)`**(待換地圖的欄位在它上面)、`app = *0x4c31ec`。目前地圖 id = `stage+0x788`,名字 = `stage+0x7a0`(Big5)。

請求層(thiscall,`this = scene`;`gs->stage == 0` 或正在換時靜默不做)—— **模組用這層**:

| 位址 | 簽名 | 說明 |
|---|---|---|
| `0x419980` | `(scene, stage, 出口 id)` | 到目標圖的某個出口。走進出口、腳本換圖都走這條 |
| `0x4198a0` | `(scene, stage, 格x, 格y)` | 到指定格 |
| `0x419a40` | `(scene, 出口索引)` | 原作走進出口時用:查出 `{目標 stage, 目標出口}` 再排程 |

執行層(thiscall,`this = gs`;**不拆舊圖,遊戲中不要直接叫**):`0x458a70(gs, stage, 出口)`、`0x458810(gs, stage, 格x, 格y)`、`0x457f50(gs, stage)`(只載圖)、`0x451180` `Stage::load(stage, id)`(讀 `stage.ini` 各欄、跑腳本 `stageExitStage` / `stageEnterStage`)。

排程欄位(scene 上):

| 偏移 | 意義 |
|---|---|
| `+0x15c` | 旗標:bit0 淡出中、bit1 本幀換圖、bit2 淡入中、`0x10` 用座標;0 = 沒在換 |
| `+0x160` | 目標 stage |
| `+0x168 / +0x16c` | 出口 id 或 格x / 格y |
| `+0x1e4`(byte) | 自動存檔待辦:淡入結束設 1(`0x4197c5`),`0x416530` 看到就寫 `exsave99.sav`(`0x425b10`) |

模組的做法(`map_tick`):
1. 把 `0x4197cb` 的立即數 `01` 改成 `00`(先比對前後位元組確定是那道指令)→ 淡入結束不會排自動存檔
2. 呼叫 `0x419980` 或 `0x4198a0`
3. 看 `scene+0x15c`:變非 0 再回到 0 = 到站 → 改回 `01`、(座標版)用 `0x454bb0` 把主角挪到可走格、印 `where`
4. 3 秒內 `+0x15c` 都沒動 = 原作沒接受請求,改回、記 log

## `stage.ini`(在 pak 裡,不在磁碟上)

讀取函式都是 cdecl:`0x46ecf0` `open("stage.ini")`(失敗 −1)、`0x46ed20` `get(0, "stage%03d\\Name", 1, out)`(查不到回 −1,**不會插入**)、`0x46ec00` `close()`、`0x450590` `stageExists(id)`。

每張圖的欄位:`Name`、`Type`、`Map`、`Z`、`Tbl`、`Jpg`、`Object`、`Script`、`Music`、`Event`、`Gateway001..`。

- **Type** 是旗標名字串,全部 OR 進 `stage+0x79c`。實際出現的名字:`STAGE_WAR`(戰鬥地圖;= 之前找到的「可戰鬥」位元)、`STAGE_SMALLMAP`、`STAGE_CANTELEPORT`、`STAGE_VISITMARK`、`STAGE_TINY`、`0`
- **Gateway** = `目標 stage, 目標出口 id`;出口在地圖上的位置不在 ini,在地圖資料裡
- **id 會被原作轉成劇情版本**:`goto_map 38` 實際進的是 238(李家莊)。看起來 2xx / 3xx 是同一張圖在不同劇情階段的版本,原作依劇情進度挑

## 實測

量法:`tools/map_test.sh`,每張跳過去等 4 秒印 `where`;每張 1 次。

| 測什麼 | 結果 |
|---|---|
| 第一次:琉璃仙境通道 → 琉璃仙洞 | 到,換圖 406 ms(請求到淡入結束) |
| 80 張戰鬥地圖連續跳 | 78 張一次到;2 張(14 天脊峰、17 天象塔入口)那一跳遊戲當掉 |
| 當掉的 2 張單獨重跳 | 都到。當掉的原因:**前一張圖的怪 4 秒內把 Lv 1 的主角打死**,原作跳出「進度讀取」選單,這時再換圖就當。加了保護:主角死了 `goto_map` 不換(實測會印 `refused`,沒當) |
| 從標題畫面 | 到(先讀自動存檔再換),約 3 秒 |
| 座標版 `goto_map 5 40 30` | 到;主角被挪了 32 px 到可走格 |
| 不存在的 id `goto_map 999` | 擋下(`not in stage.ini`) |
| 自動存檔 | `exsave99.sav` 的 md5 在第一次跳、從標題跳、座標版跳之後各比一次,都沒變 |

掃出來的地圖大小(下表):寬或高 ≥ 1900 px 的大圖 27 張(最大的品茗鎮 3200×3360、鳴劍山莊通道 / 大樹林通道 2560×1920);44 張被原作轉成 +200 的版本;10 張進去時沒有怪。

**寬的地圖怪會包圍**:在三重天通道(1280×960,空地)跑倖存者,怪從四面圍上來(場上 76 隻,FPS 51),不是通道圖那種排隊 —— 補上 [05](05-enemy-walk.md) 沒驗到的那一點。

**等級問題**:存檔的素還真是 Lv 1。跳到中後期的圖(李家莊、天脊峰通道二、一重天)4–12 秒就被原作的怪打死。Roguelite 要用這些圖,得把圖上原作的怪清掉或壓數值(模組生的怪已經有打折機制,原作自帶的沒有)。

## 還沒做 / 不知道

- 進圖一定會跑那張圖的進場腳本(`stageEnterStage`)與 `Event`,**有些圖可能觸發劇情**;這輪 80 張沒有看到卡住的劇情演出(每張只等 4 秒、存檔是剛開局的進度);竹林通道二(261)進去時橋上站著幾個劇情 NPC。別的劇情進度會不會不一樣不知道
- 劇情版本(+200 / +300)是原作依進度挑的,模組沒有指定「我要哪個版本」的辦法(直接下 `goto_map 238` 沒試出差別)
- 出口版要給目標圖真的有的出口 id;給錯原作會載了新圖但主角沒放好(靜態看到的,沒去踩)。`goto_map ID` 會先查 `Gateway001` 存不存在
- 「開新遊戲直接進某張圖」原作留有一條除錯路徑(`app+0x94 == 1` 時開機直進 `app+0x98` 那張圖),沒試;現在是先讀存檔再跳
